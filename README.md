# 🏆 Python vs Спорт

Добро пожаловать в **Python vs Спорт** — веб-платформу для проведения соревнований по программированию, хакатонов и олимпиад с автоматической проверкой кода.

Проект создан с упором на простоту развертывания и современный UX: участникам доступен продвинутый редактор кода с подсветкой и подсказками, живой таймер, а также виртуальная песочница для тестирования решений до отправки. Вам не нужно быть системным администратором, чтобы запустить платформу — достаточно одного клика!

---

## 🚀 Быстрый старт (Windows)

Мы подготовили полностью автоматический скрипт установки, который сделает всё за вас.

1. Скачайте папку с проектом (или склонируйте репозиторий).
2. Найдите файл **`install.bat`** и запустите его двойным кликом.
3. Сядьте поудобнее и наблюдайте. Скрипт:
   * Проверит наличие **Python 3.12** и **Git**. Если их нет — автоматически скачает и установит в тихом режиме.
   * Скачает актуальные файлы проекта.
   * Создаст виртуальное окружение (`.venv`) и установит все зависимости.
   * Сгенерирует надежный `SECRET_KEY` и создаст файл конфигурации `.env`.
   * Откроет порт `8000` в брандмауэре Windows.
   * Запустит локальный сервер, выведет IP-адреса для подключения и откроет сайт в вашем браузере.

> **Важно:** При первом запуске установка Python и Git может занять несколько минут. Пожалуйста, не закрывайте черное окно консоли во время установки!

## 🐧 Установка на Linux / macOS

Для пользователей Unix-подобных систем предусмотрен аналогичный скрипт на Bash.

1. Откройте терминал и перейдите в папку с проектом.
2. Дайте скрипту права на выполнение:
   ```bash
   chmod +x install.sh
   ```
3. Запустите его:
   ```bash
   ./install.sh
   ```

> **Требования:** Python 3.12 обязателен (для 3.13/3.14 нет готовых wheels `pydantic-core` → ошибки `maturin`). На Debian Trixie используйте `pyenv` для установки Python 3.12.

## 🌐 Как подключиться с другого устройства (Телефон, Планшет, Другой ПК)

По умолчанию сервер доступен только на том компьютере, где он запущен (`http://localhost:8000`). Чтобы зайти на сайт с телефона или другого ноутбука:

1. Убедитесь, что оба устройства подключены к **одной и той же Wi-Fi сети**.
2. При запуске сервер выведет в консоль список доступных IP-адресов. Найдите тот, который относится к вашей локальной сети (обычно начинается на `192.168.x.x` или `10.x.x.x`).
3. Введите этот адрес (например, `http://192.168.1.55:8000`) в браузере на вашем телефоне.
4. **Если не работает:**
   * Проверьте, что брандмауэр не блокирует порт `8000` (скрипт пытается открыть его автоматически, но иногда требуются права Администратора).
   * Убедитесь, что ваш Wi-Fi роутер не использует «Изоляцию клиентов» (Client Isolation). В таком случае используйте «Мобильный хот-спот» на Windows для создания прямой связи.

Проект разделен на два основных логических блока: **`web`** (пользовательский интерфейс и API) и **`orcestrator`** (фоновая логика проверки кода).

```text
Python_VS_Sport/

│
├── orcestrator/             # ОРКЕСТРАТОР (Бэкенд-логика проверки)
│   ├── logs/                # Логи работы оркестратора, report.json, session.log, crash.log
│   ├── tasks/               # Папка с файлами задач (task.txt, tests.json)
│   ├── batch_runner.py      # Запуск тестов, замер времени и памяти (psutil)
│   ├── checker.py           # Ядро проверки: прогон и сравнение с эталоном
│   ├── code_reader.py       # Модуль чтения и парсинга присланного кода
│   ├── config.py            # Загрузка конфигурации
│   ├── logger_setup.py      # Настройка логирования (файлы + консоль)
│   ├── main.py              # Точка входа оркестратора (CLI)
│   ├── pool.py              # Пул воркеров (ProcessPoolExecutor)
│   └── reporter.py          # Формирование отчётов в stdout и report.json
│
├── web/                     # ВЕБ-ПРИЛОЖЕНИЕ (Фронтенд + API)
│   ├── app/                 # Исходный код FastAPI (роуты, шаблоны, модели)
│   ├── contest_web.db       # База данных SQLite
│   └── run.py               # Умный запуск сервера (определение IP, порты)
│
├── install.bat              # Скрипт автоустановки для Windows
├── uninstall.bat            # Удаление проекта и правил брандмауэра (Windows)
├── install.sh               # Скрипт автоустановки для Linux/macOS
├── uninstall.sh             # Удаление проекта (Linux/macOS)
├── requirements.txt         # Зависимости Python
└── README.md                # Документация проекта
```

## ⚙️ Как работает программа (Под капотом)

Система разделена на два независимых процесса: **Веб-сервер (Web)** и **Оркестратор (Orchestrator)**.

1. **Взаимодействие с пользователем (Web-часть):** Веб-сервер на базе **FastAPI** обрабатывает запросы. Студент авторизуется (пароли хешируются bcrypt, сессии защищены JWT-токенами в HttpOnly-cookie). Все данные сохраняются в локальной базе **SQLite**.
2. **Фазы и таймеры:** В админ-панели задаётся список фаз (задача / спорт) с `order_index`, `duration_seconds`. У каждой команды свой прогресс по фазам (`started_at`, `current_phase_index`, `phase_started_at`). Таймер стартует при первом заходе команды на `/team`. Переход между фазами — автоматический по истечении времени или принудительный из админки.
3. **Очередь и запуск:** Когда пользователь отправляет код, веб-сервер подменяет `solution.py` в папке задачи, вызывает `orcestrator/main.py tasks --only {id}`, читает stdout и сохраняет результат в БД.
4. **Проверка кода:**
   - `code_reader.py` читает и валидирует файл решения.
   - `checker.py` прогоняет тесты через `batch_runner` с ограничениями по времени и памяти.
   - `batch_runner.py` запускает решение в изолированном процессе с заблокированными опасными импортами (`os`, `sys`, `ctypes` и т.д.). Замер пиковой памяти (`psutil`) идёт **в отдельном потоке параллельно** с работой процесса — иначе короткоживущие процессы не успевают замериться. В результат каждого теста возвращаются `time_ms` и `memory_mb`.
   - `reporter.py` печатает отчёт в stdout (`[ OK ] #1 (+10) time=71.5ms mem=3.4MB`) и сохраняет `logs/report.json`.
5. **Возврат результата:** Веб-сервер парсит stdout оркестратора (`Результат: X/Y`, `time=...ms`, `mem=...MB`), сохраняет `Submission` с полями `score`, `time_ms`, `memory_mb`, `time_spent`. Клиенту результат приходит через WebSocket (`update_rating`, `timer_changed`, `tasks_changed`).

## 📊 CSV-экспорт

В админ-панели кнопка **«ЭКСПОРТ CSV»** выгружает `/api/admin/export`:

* Кодировка — **UTF-8 с BOM**, разделитель `;`, окончание строк `\r\n` (RFC 4180). Excel открывает без «кракозябр».
* Колонки: «Место», «Команда», «Школа», «Баллы (Код)», «Баллы (Спорт)», «Итого», а также для каждой задачи: «Баллы», **«Время, мс»**, **«Память, МБ»**.
* Для каждой задачи выбирается **лучшая** посылка: сначала по баллам, затем по меньшему `time_ms`, затем по меньшей `memory_mb`.

## 🛠 Ручной запуск (для разработчиков)

Если вы хотите запустить сервер без автоматического установщика:

1. Активируйте виртуальное окружение:
   * **Windows:** `.venv\Scripts\activate`
   * **Linux/macOS:** `source .venv/bin/activate`
2. Перейдите в папку веб-приложения:
   ```bash
   cd web
   ```
3. Запустите сервер:
   ```bash
   python run.py
   ```
Сервер будет автоматически перезагружаться при изменении файлов (режим `reload=True`).

### Запуск оркестратора вручную

Для отладки проверки кода без веб-сервера:

```bash
cd orcestrator
python main.py tasks --only 1
```

Выведет отчёт по задаче №1 в stdout и сохранит `logs/report.json`. Опции:
* `--workers N` — число воркеров (по умолчанию из `.env`);
* `--max-load X` — ждать, пока load average не упадёт ниже X;
* `--report-json PATH` — куда сохранить отчёт (по умолчанию из `.env`).

Основные (см. `requirements.txt`):

* `fastapi`, `uvicorn` — веб-сервер
* `sqlalchemy` — ORM
* `jinja2` — шаблоны

## ❓ Частые проблемы (FAQ)

**1. Ошибка `Permission denied` при установке.**
Это происходит, если вы запускаете `install.bat` из системной папки. Скрипт автоматически переносит установку на Рабочий стол, но убедитесь, что вы запускаете его из обычной папки.

**2. Консоль закрывается моментально при запуске `install.bat`.**
Откройте командную строку (`cmd`) вручную, перейдите в папку с проектом и запустите `install.bat`. Так вы сможете увидеть текст ошибки.

**3. С телефона не открывается сайт, хотя IP-адрес введен верно.**
Скорее всего, брандмауэр Windows блокирует подключения. Запустите `install.bat` от имени Администратора, чтобы скрипт создал правило для порта 8000.

**4. Сервер пишет `[СЕТЬ] Не удалось открыть порт`.**
Запустите терминал (или `install.bat`) от имени Администратора. Windows требует повышенных привилегий для изменения правил брандмауэра.

**5. Код выдает `Wrong Answer`, хотя локально всё работало.**
Проверьте, не выводите ли вы лишние подсказки в `input()` (например, `input("Введите число: ")`). Проверяющая система сравнивает **весь** вывод программы с эталоном.

**6. В CSV пустые колонки «Время, мс» и «Память, МБ».**
Убедитесь, что установлен `psutil` (`python -c "import psutil; print(psutil.__version__)"`). Проверьте, что в `orcestrator/logs/session.log` есть строки `Тест #1: rc=0, time=...ms, mem=...MB`. Если `mem=0.0MB` на очень коротких процессах (1–2 ms) — это ограничение `psutil`, для реальных решений (десятки ms) память замеряется.

**7. В CSV «кракозябры» вместо русских букв.**
Файл уже генерируется в UTF-8 с BOM (`\ufeff`). Если Excel всё равно показывает некорректно — откройте через «Данные → Из текста/CSV», выберите кодировку UTF-8, разделитель `;`.

**8. Python 3.13/3.14 — ошибки `maturin` / `pydantic-core` при установке.**
Проект требует **Python 3.12**. На Linux установите через `pyenv install 3.12` и активируйте перед `pip install`.
